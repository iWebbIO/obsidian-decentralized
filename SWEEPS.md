# V3 Release Audit — 50 Sweeps

Each sweep is one focused audit pass with a specific target and lens. Outcome is one of:
- **FIX** — defects found, fixed, pinned by tests (commit hash noted)
- **CLEAN** — no defects; evidence recorded (what was checked and why it holds)

Ledger is append-only per sweep. No sweep may be marked done without either a commit
containing its fix or a recorded justification with specific evidence.

| 1 | settings-tab.ts | input validation, settings corruption | FIX — custom signaling server host/path accepted anything; "wss://server" (PeerJS docs' own spelling) built an unresolvable URL in `new Peer()` and the retry loop ran forever. Now normalized at input (settings-tab) and self-healed at load (main.ts loadSettings); helpers pinned in net.test.ts. | 2 | ui.ts ConnectionModal + pairing flow | logic, race, leak | FIX — 11 defects: (1) "Discovered Hosts" listed standard-mode peers (no port, nothing listening) whose Select dead-ended in a 20 s failure; now only direct-ip beacons WITH a port are offered. (2) An Offline-Mode device armed a pairing window and broadcast a pairing key its mode cannot honour — nearby taps on it always failed; the window is skipped in direct-ip mode and getMyPeerInfo no longer advertises a key there. (3) The 30 s pairing-refresh interval was created AFTER an await, so closing during the mint leaked an interval that re-armed enrolment forever; armed first with a closed-flag backstop. (4) beginPairingWindow had no unloaded guard (refreshLanBeacon did), so a modal left open across unload re-armed on the dead plugin. (5) watchDirectIpClient stopped permanently at its 20 s timeout — a later host recovery or fatal token rejection never surfaced; it keeps polling at 2 s, re-rendering only on state change. (6) The join Connect button could double-fire (second call tore down the first client mid-handshake + a spurious "Disconnected" toast); disabled across the sequence. (7) Pasted pairing codes had no length caps (inbound peer info does): a megabyte-scale "key" could be filed into data.json; deviceId capped at 128, PSK pattern capped at 64 bytes. (8) All three mode switches dropped every live connection on one unconfirmed click; now behind ConfirmModal. (9) A failed save during a mode switch left settings claiming the new mode while the engine ran the old (reverting only after restart); now rolls back in memory + Notice. (10) A late 'error' event overwrote a successful pairing with a failure card; ignored once paired. (11) The QR callback fired per decodable frame before async stop() halted the camera — one-shot flag. Also: the 10-min renewal no longer re-renders the tab (wiped in-progress paste input) and renews before expiry so the label never reads "expired"; paste auto-submit tracked and cleared on close; Offline Mode's banner no longer says "Ready to pair". | (this commit) |
| 3 | ui.ts remaining modals (QR, progress, confirm, binary conflict) | logic, error paths | FIX — 9 defects: (1) conflict-resolve callbacks ran fire-and-forget, so a failed vault write/trash died as an unhandled rejection with the badge stuck and zero feedback; the modals now observe the promise and Notice failures. (2) The resolution modal could stay open while background sync wrote newer content — choosing the conflict copy then silently clobbered it; the choice now re-checks freshness (content for text, mtime for binary) and refuses to overwrite, keeping the conflict listed; pinned by test. (3) ConfirmModal likewise fire-and-forget for its async confirmers (device reset, forget, mode switch) — now observed. (4) The Sync Progress "Failed Ns ago" readout froze (failures not in the busy set) and showed "Attempt 0" for a pending first try — both fixed. (5) Items parked in retry backoff were invisible to every structure the modal reads ("Nothing is syncing right now" while work was pending): QueueManager now exposes getRetrying() (pinned by test) and the "Waiting to send" label became "Sending N recent changes…". (6) Conflict copies whose original was deleted became permanently invisible orphans — the copy is the only surviving edit; scanVault now keeps them and the list offers Restore-as-original / Delete-copy; pinned by 3 tests. (7) Unchecked `as TFile` casts on getAbstractFileByPath could hand a TFolder to the binary modal → uncaught throw; instanceof guards added. (8) requestFullSyncFromPeer's pre-try state mutations were unguarded — a sync throw there left isSyncing=true with a floating rejection; the whole body is now inside the try. (9) A paused transfer's ETA kept growing while nothing moved ("Paused — no estimate" instead) and a dead conditional in SelectPeerModal removed. | (this commit) |
| 4 | types.ts | constants sanity, payload shapes vs handlers | FIX — 10 defects: (1) the chunk-count ceiling divided by MAX_CHUNK_SIZE (128 chunks) so any legal transfer with adaptive 512KB chunks over 64MB was rejected forever — the sender burned its full 300s ack window per attempt; ceiling now divides by MIN_CHUNK_SIZE (8192), pinned by test. (2) REQUESTING_TIMEOUT equalled PLANNING_TIMEOUT, so a responder using most of its planning budget made the requester abort first; now PLANNING + 30s, pinned by test. (3) BATCH_TIMEOUT was never re-armed by transfer progress — a slow link moving data all along could still abort mid-batch; chunk and batch arrival now re-arm the TRANSFERRING timer. (4) abortSync missed pendingFileChunks: aborted reassemblies pinned preallocated buffers and reassembly slots for 5 minutes, so a restarted sync could be refused new chunked transfers; pinned by test. (5) getChunkSize returned settings.chunkSize unclamped — a hand-edited data.json over MAX_CHUNK_SIZE made every received chunk fail validation while the sender kept sending; now clamped, pinned by test. (6) Download-side TransferStatus lacked chunkSize, so UI byte math fell back to the drifting adaptive default. (7) Progress accounting mixed directions and double-counted: bytesTransferred counted sent chunks against a pull-only bytesTotal and received chunks twice (per-chunk + batch-complete); now counted once at batch-complete; filesTransferred now also counts served files so the bar moves on a serve-only device. (8) The direct-IP skipAck flag was computed but never travelled on the wire, so receivers acked batch items the protocol says not to; now set and modelled in the type. (9) Dead code removed: COMPLETING_TIMEOUT (unreachable), InitiatorSyncDonePayload, SyncState.phaseStartTime, HandshakePayload.pin + the never-passed pin params, MAX_QUEUE_DEPTH + the getQueuePressure chain that nothing called. (10) Control payload types now model the messageId the wire actually carries; FileBatchBinaryPayload declares its transferId; mtimeTolerance documented as manifest-equality-only (threading it into conflict decisions would break cross-device determinism — versions.ts doc + reworded setting). | (this commit) |
| 5 | core/storage impls (NodeFs, InMemory) | edge cases, contract honesty | FIX — 8 defects: (1) NodeFs resolveSafePath prefix check had no separator boundary → sibling-directory traversal reachable from the wire; (2) empty path resolved to the vault root → delete('') wiped the whole tree on NodeFs; (3) NodeFs stat() reported folders as files (InMemory said null); (4) InMemory silently allowed rename onto a folder-occupied destination — an impossible state the Merkle tree overwrote, stranding the file from every diff — and silently no-op'd missing-source renames; (5) NodeFs delete emitted an event for already-gone paths and one event for whole folders (InMemory: per-file), leaking hashCache entries forever; (6) NodeFs write reported the REQUESTED mtime even when utimes best-effort failed — surrogate-hash comparisons for large files never converged; (7) trailing-slash paths produced event keys that didn't match listFiles keys, defeating cache invalidation; (8) TEXT_EXTENSIONS existed as two manually-synced copies (and both omitted 'yml' — conflict merges silently degraded to whole-file replacement for .yml). All fixed; contract documented in IVaultStorage; VirtualDevice now catches dispatch errors (was unhandled-rejection-prone) and invalidates rename old-paths; MerkleManager hashCache capped. 6 new contract tests run against all three implementations (39 storage tests). | (this commit) |
| 6 | main.ts | floating/unawaited promises | FIX — saveKnownPeers was fire-and-forget at every call site but rejected on a saveData disk failure (unhandled rejection, also through the void-forgetDevice chains); now logs instead. handleClusterRename floated saveSettings in a sync handler; now .catch-logged. Verified sound with evidence: requestLock (resolve-only), sendFileUpdate (queues only, no awaits), processIncomingData (try/catch + caller-chain catch), folder apply handlers (inner try/catch + runLocked semantics), saveState/saveHashCache/saveQueueState (writeJsonAtomic internal catch), all .then chains (each has .catch). | (this commit) |
| 7 | main.ts | peer-input validation per message type | FIX — 3 defects: (1) applyFileUpdate branched on `encoding` but never checked the content's actual type — a text-encoded update carrying binary content reached vault.modify and wrote "[object ArrayBuffer]" into the note (silent corruption from one malformed message); now refused with IntegrityError → nack → the sender falls back to a full send. (2) Non-finite mtimes (NaN/Infinity) flowed into conflict math and the vault's own stat; refused in applyFileUpdate, applyFileDelta and file-chunk-start. (3) cluster-forget/kick acted on arbitrary peer-supplied targetDeviceId strings — one malformed message could grow blockedPeers (and data.json) without bound; both now require a device this vault knows, and cluster-rename validates its fields. Verified sound with evidence: every path field passes sanitizeVaultPath via canonicalizePeerPaths; version vectors sanitized; sync-plan/batch paths re-validated against the authorized-pull set; manifest entries scope-checked; merkle children used as compare-keys only; lock requestIds are map keys; chunk fields fully bounds-checked. Pinned by 5 new tests (scope + cluster). | (this commit) |
